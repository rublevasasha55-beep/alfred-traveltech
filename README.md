# Альфред — План Б для путешествия

Учебный проект по кейсу ИТ-аналитики: TravelTech-система, которая получает сведения о задержках или отменах рейсов, оценивает влияние на поездку, рекомендует допустимые альтернативы и предлагает пользователю согласовать изменения.

**Главная идея:** не просто уведомлять «рейс задерживается», а показывать, *что именно ломается в путешествии*, и предлагать обоснованный «План Б» с учётом пересадки, багажа, виз, часовых поясов и группы путешественников.

Дизайн вдохновлён нашим предыдущим учебным проектом Landing Monitor: светлый интерфейс, белые карточки, графитовые заголовки, жёлтые акценты и векторные иконки. Это самостоятельная учебная работа, **не официальный сервис Т-Банка**.

## Запуск на Mac в VS Code

Открой папку проекта в VS Code и в терминале последовательно выполни:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

Браузер откроет `http://localhost:8501`.

### Проверка сценария

1. На главном экране нажми **«Смоделировать задержку +120 мин»**.
2. Проверь, что пересадка уменьшилась до **20 минут** при необходимом минимуме **90 минут**.
3. Открой **«План Б»**: допустимые варианты доступны для согласования, а неподходящие помечены конкретными причинами (время пересадки, багаж, визы).
4. Выбери допустимый рейс. Изменится **черновик** общего плана, а трансфер будет помечен как требующий пересогласования. Реальных бронирований нет.
5. В **«Уведомлениях»** переключись в офлайн, затем создай новое событие и верни онлайн — уведомления будут доставлены из локальной очереди.
6. В **«Симуляторе»** проверь повтор `event_id` и устаревшее событие.

## Локальное демонстрационное API (по желанию)

Оставь приложение Streamlit работающим. Во **втором терминале** с тем же `.venv` запусти:

```bash
python -m uvicorn demo_api:app --host 127.0.0.1 --port 8000
```

Swagger: http://127.0.0.1:8000/docs. Там можно отправить событие в `POST /api/events`, посмотреть `GET /api/trips/demo` и `GET /api/trips/demo/alternatives`. API и приложение используют общий файл состояния в `storage/`, поэтому после обновления страницы Streamlit состояние совпадёт. Используется только локальная имитация поставщика, без реальных внешних API.

## Структура проекта

- `app.py` — UI и сценарии в Streamlit;
- `ui.py` — общий визуальный стиль;
- `engine.py` — бизнес-правила обработки событий, проверки ограничений и обновления плана;
- `demo_api.py` — локальный API на FastAPI;
- `store.py` — демонстрационное сохранение состояния;
- `docs/sequence.mmd` — sequence diagram;
- `docs/architecture.mmd` — архитектура;
- `docs/ANALYST_NOTES.md` — требования, критерии приёмки, границы MVP;
- `tests/` — автоматические проверки.

Запустить тесты: `python -m pytest -q` (после установки `requirements-dev.txt`).

## Ограничения и приватность

Все рейсы, цены, визовые статусы, люди и другие данные **вымышлены**. Приложение не подключено к авиакомпаниям, не отправляет сообщения в реальные каналы, не принимает платежи и не перебронирует билеты. В нём нет паспортных данных. В промышленном решении паспортные данные должны храниться только на период объективной необходимости, с учётом правовых требований, и удаляться по установленному процессу.

Локальное API не имеет production-аутентификации
